# 安全并发与部署加固实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 按任务逐项执行并在每项后验证；仓库禁止新增测试文件。

**目标：** 在保持现有功能和接口兼容的前提下，收敛依赖安全、请求并发保护、远程部署和生产运行风险。

**架构：** 优先使用现有 Express、Compose、部署脚本和运行时配置。所有限制采用可配置默认值，保留单实例默认行为；只有明确安全边界的输入才直接拒绝。

**技术栈：** Bun、TypeScript、Express、MySQL、Docker Compose、GitHub Actions。

**依据：** `docs/superpowers/plans/2026-10-15-web-chunk-optimization.md` 及本轮安全、并发和部署审计结果。

## 全局约束

- 不新增运行时依赖或测试文件。
- 不改变现有 API 路径、页面默认状态、工作区文件格式和保存时机。
- 生产限制必须有明确的错误响应，不能吞掉业务异常。
- 当前环境无法替代真实 Docker、MySQL、远端服务器和 100+ 并发验证；必须记录验证边界。

### 任务 1：依赖和服务端安全边界

- 修复仍可安全修复的高危依赖。
- 限制上游错误详情和外部 URL 信任边界。
- 验证服务端类型检查和依赖安装。

### 任务 2：并发保护和运行配置

- 保留现有连接池可配置能力。
- 为高成本 Agent、媒体和上传入口增加可配置的并发保护。
- 增加运行期健康、限流或排队所需的最小配置，不改变单实例默认体验。

### 任务 3：远程部署加固

- 收紧容器权限、镜像来源、备份和磁盘检查。
- 固定 CI action 和可变基础镜像的安全边界。
- 保留回滚和现有数据卷兼容性。

### 任务 4：验证和审计记录

- 运行类型检查、构建、依赖安装、脚本语法和差异检查。
- 明确 Docker、真实数据库、浏览器流程和并发压测的环境限制。

## 本轮结果

- [x] Web chunk 拆分、异步组件和 vendor 分包已完成，保持现有页面默认状态与保存时机。
- [x] 插件下载与远端 A2A 使用统一的公开地址策略，生产默认拒绝内网目标；重定向逐跳校验并固定 DNS 解析结果。
- [x] Agent、文本/媒体流式错误统一脱敏；日志与生成账单错误不再直接保存上游凭据、路径和堆栈。
- [x] Agent、媒体、FFmpeg、大文件上传增加可配置的单进程并发上限，超限明确返回 429/Retry-After。
- [x] MCP 依赖更新到无当前审计告警的兼容版本，`undici` 使用 8.10.2 根级覆盖；路由 glob 关闭不必要的 brace 展开。
- [x] Compose、镜像 digest、非 root 容器、备份权限/可选加密、磁盘 inode 预检和 CI action 固定已完成。

仍需在对应环境执行：Docker build/compose up、真实 MySQL 迁移与恢复演练、远端服务器反向代理和防火墙核验、浏览器回归，以及 100+ 并发压测。当前 `bun audit` 剩余告警来自构建或间接依赖（`decode-uri-component`、`braces`、KaTeX、esbuild）；已对实际路由 glob 关闭 brace 展开，其他项目需等待上游兼容版本或单独升级评估。
