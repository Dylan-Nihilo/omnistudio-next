# 分镜成熟产品交互对齐与验收记录

**日期：** 2026-11-16（北京时间）<br>
**分支：** `codex/enterprise-comic-p0`<br>
**范围：** 按灵境实际可观察到的分镜工作区改造镜头查看、编辑、增删和 AI 分镜入口。

## 参考实测

- 灵境短剧 `sd_MTU3Mg` 的第 3 步为独立分镜工作区，左侧按剧集切换，主区域先显示当前集标题，再显示可横向滚动的结构化镜头表。
- 表格列为序号、时长、景别、角色、场景、道具、光影、音效、对白、旁白、镜头控制和画面描述。点“编辑”后整表进入编辑态，顶部提供“提交/取消”，每行可以在当前位置后新增或删除，角色/道具通过多选资产列表关联。
- 页面底部显示待生成分镜数量、按消耗计费说明和生成入口。实测项目有 4 集待生成，入口为“全部生成”。本地项目按当前集生成，保留已有报价和用户确认流程，不批量触发其他剧集。
- RunningHub RH STORY 的公开资料证明剧本到分镜的阶段流程，但没有证据证明其采用同样的待审草稿事务模式；无限画布不作为生产项目分镜页的模板。[RunningHub 调研](runninghubAgentSkillCanvasProjectResearch20261115.md)

## 本轮实现

- 正式镜头改为整集表格编辑。点击“编辑”后所有字段在原表格内修改，角色和道具使用可筛选多选，景别与场景使用选择器；新增行插入当前行后，删除和重排在点“提交”前只保留于本地，点“取消”还原。
- 新增整集保存 API，在服务端事务中验证项目权限、剧集和资产归属，重排镜头唯一编号，并保存新增、修改和删除。已进入生成/审片状态或已有媒体候选的镜头不能被整集覆盖；删除时也检查候选、审片和批准记录。
- 表格调整为灵境观察到的 12 列，收窄列宽并移除分镜步骤中的重复阶段摘要和侧栏资产计数，保留剧集侧栏与本集镜头/场景计数。草稿的场景标题和连续性说明保留在该场景第一行的场景单元格中。
- 空剧集的 AI 分镜草稿沿用模型选择、积分预估、生成确认、草稿版本冲突保护和确认写入流程；AI 模型、报价和“AI 生成分镜脚本”移到表格下方的吸底操作条。该入口仅用于尚无正式场景的当前集，避免覆盖已确认镜头。

## 当前结论

分镜镜头的表格列、编辑入口、行后新增/删除、资产多选和提交/取消已按灵境实测交互落地。正式镜头使用原子整集保存，AI 草稿继续保留报价与版本保护。真实 API 提交和空剧集的 AI 操作尚未做端到端业务验证；本轮没有触发积分消耗，也没有保存任何本地验收改动。
