# 生产项目创作链路实测与持久化修复

日期：2026-11-07  
分支：`codex/enterprise-comic-p0`

## 实测对象

本次核验使用当前功能创建的项目，不使用旧演示项目。

- 项目 ID：`67f20b25-ea00-40c5-9715-520c1e185d68`
- 项目预算：1600 积分
- 当前状态：已编剧，已进入主体资产步骤
- 实际保存：1 季、1 集、3 场、12 镜头、5 项资产
- 镜头时长：合计 60 秒

## 已核验行为

1. 创作入口的输入、题材、融合题材、风格、画幅和集数组成项目草稿；入口点击只创建项目并保存草稿，不会自动调用模型。
2. 项目页按项目 ID 从服务端恢复同一份草稿，输入框是可继续编辑的工作区，不要求重新输入。点击费用预估和确认生成后才会请求文本模型。
3. 生成链路把题材约束、视觉风格正向/排除提示和创作内容组合后发送到文本生成接口；确认后把剧集、场景、镜头、资产及创作规格保存到项目。
4. 正式结构提交成功后，草稿查询接口返回 `draft: null`、`revision: 0`。数据库只读核验结果为 1 集、3 场、12 镜头、5 项资产，项目预算为 1600 积分。

## 发现的问题

- **正式保存会丢失模型原文。** 原始模型响应和用量曾保存在临时草稿的 `generationData` 中；确认剧本时，服务端事务删除临时草稿，却没有把原文转存到永久记录。当前项目的临时草稿和永久生成记录都为空，因此无法从现有持久化数据恢复这次模型原文。
- **项目创建与首份草稿不是一个事务。** 入口先创建项目，再单独保存草稿；两次请求之间失败会留下空项目。页面内重试能复用当前内存中的项目，但刷新会失去这个关联。
- **附件只保存在当前浏览器 IndexedDB。** 服务端草稿只保存附件元数据和本机存储键。换浏览器或设备无法恢复原文件，尚不符合企业级项目文件存储要求。
- **DOC/DOCX 不会自动提取正文。** 当前模型引用正文读取支持范围有限；上传文件作为附件保存，不代表文件正文已进入模型请求。

## 本次实现

- 入口创建项目时同时提交初始剧本草稿；项目、成员、创建审计和初始草稿在同一数据库事务中提交，草稿从 revision 1 开始。后续附件引用仍按草稿 revision 乐观锁更新。
- 正式保存剧本时，在同一事务内保存原始模型响应、模型与用量元数据、题材/风格参数及用户确认后的结构快照，然后删除临时草稿。任一步失败会整体回滚，避免结构已写入但审计记录缺失。
- 新增按项目读取剧本生成历史的只读接口，受登录和项目读取权限保护，并设置 `Cache-Control: no-store`。
- 新增迁移 `userIdentityProduction08ScriptRecords.sql`；本地数据库迁移表已确认该迁移完成。

## 验证范围

- 实际页面核对：项目处于主体资产步骤，资产与剧本结构已保存。
- 实际 API 核对：草稿读取返回空值，表示正式结构保存后临时草稿已清理。
- 数据库只读核对：项目状态、预算、剧集/场景/镜头/资产计数及草稿/生成记录计数。
- 本次代码修改后：服务端与前端 TypeScript 类型检查通过；服务端与前端构建通过。历史接口未登录请求返回 401，符合权限保护预期。
- 本次代码修改后的“重新调用模型并确认结构”尚未再次点击验证，避免重复产生模型费用；已完成的真实项目发生在本次归档修复之前，因此其原始响应无法补回。

## 当前边界

剧本文字和生成记录现在走服务端 MySQL 持久化；附件仍依赖当前浏览器本地存储。企业商用前，附件需要改为项目权限保护的服务端对象存储，并保留附件版本、上传者、校验和及访问审计；同时应提供 DOC/DOCX 正文解析或明确阻止把未读取正文的文件误当作模型输入。
