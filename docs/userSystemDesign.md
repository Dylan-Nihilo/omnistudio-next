# 用户、团队资产与个人积分重构

## 目标与边界

- 平台管理只保留 root。用户可以独立注册、登录，创建团队后自动成为 owner。
- 个人项目、资产、会话、设置、记忆默认私有；团队不自动获得这些内容。
- 团队共享资产由成员显式上传生成副本。团队 owner 与 root 管理共享资产，成员拥有浏览、下载和上传能力。
- 积分归用户，生成、Agent 和服务凭证调用均扣调用者个人账户。团队不创建公共钱包。
- 划转仅限同一团队的当前成员，不允许划转冻结积分、负数、非安全整数或向自己划转。
- root 可配置平台 API 凭据、模型、价格，管理用户与积分，并访问各页面；普通用户不得通过接口直接获得平台凭据或管理能力。
- 保留原有画布、节点、素材、文档和会话格式；现有 5 个项目迁移为首个 root 的个人项目，保留可恢复备份。

## 数据与权限

- 账户与平台角色、个人设置、团队与成员、邀请、项目所有权、个人钱包、转账和审计分别记录；用户侧团队仅 owner/member。
- 文件读写必须先验证认证主体与项目归属，再执行既有路径、真实目录、符号链接及文件占用校验。取消本机来源可绕过所有权的行为。
- 所有写接口统一校验会话 CSRF；公开注册、登录及首次 root 初始化只豁免认证，不豁免来源校验。
- 首次 root 初始化由数据库锁串行化；注册请求不能指定平台角色。禁用账户和密码修改撤销会话。
- 平台插件安装、供应商源码执行、FFmpeg 安装、全局服务设置与桌面更新属于 root 管理能力；普通用户可使用已安装的可信能力。
- MCP/A2A 凭证必须绑定用户；连接、任务、工具、资源与计费均使用该用户权限。不得复用全局凭证跨用户读写或绕过积分。
- 请求与异步任务携带服务端确定的用户上下文；不信任请求中的 userId、目录、团队 ID 或前端角色。
- 团队资产下载验证当前成员关系。退出或被移除后立即失去访问权；个人原件始终保留。
- 积分划转在同一 MySQL 事务中校验成员、按固定顺序锁定钱包、记双边流水与审计；重复幂等请求返回原结果，参数不一致返回冲突。
- 生成预留、成功扣除、失败/取消释放与幂等记录沿用同一用户钱包；不得使用其他用户的任务 ID 结算。

## 页面与全链路适配

- 注册、登录和首次 root 初始化：沿用原生黑橙主题、Logo、现有控件，支持邀请注册、错误保留输入、密码显示及返回路径。
- 个人账户：资料、修改密码、个人余额/冻结/流水、同团队成员划转与明确的提交确认。
- 团队：创建、切换、成员邀请与接受、退出、owner 移除成员、资产浏览/上传/下载/重命名/删除；危险操作确认目标与影响。
- 个人素材库：明确的上传到团队操作，文件由现有工作区文件入口读取，不自动同步或收集。
- root 管理：用户、团队/资产、平台 API 与模型、积分发放/调整、价格配置及审计入口；页面路由和接口双重鉴权。
- 首页、项目选择、画布、文档、Agent、节点调用、媒体生成、MCP、A2A、工具插件、FFmpeg、设置与桌面桥接全部检查，不保留旧 Workspace 公共钱包入口。
- 登录切换必须清理 Pinia、个人设置缓存、模型缓存、项目引用、连接和进行中的请求；防抖保存不得写入新登录用户。

## 验收证据

- MySQL 迁移、原数据备份与项目文件校验；升级不能静默丢弃原积分或成员关系。
- 类型检查、UI/Web/server/内置节点工具构建；不新增测试文件、测试框架或自动检查入口。
- 使用独立验证库和临时个人文件执行 root、两个同团队成员、团队外用户的实际 HTTP 权限矩阵。
- 验证注册角色注入、会话撤销、CSRF、路径遍历/符号链接、跨用户项目/资产/设置/会话、非成员团队访问和非 owner 管理拒绝。
- 验证积分划转余额守恒、冻结保护、并发、重复请求、请求参数冲突和双方流水；验证所有生成入口使用个人计费并拒绝越权。
- 浏览器验证注册登录、个人空间、团队资产、划转和 root 页面；检查键盘、移动宽度、错误与长内容，无未经授权的付费调用。
- 逐项对照本设计与原始需求检查最终实现和运行证据，完成前不把基础结构或单一通过检查视作完整交付。

## 最终实施状态（2026-10-09）

用户、权限、个人计费、团队资产、原生 UI 与服务调用适配已经落地，完整覆盖表和实际验收记录见 [交付报告](userSystemReport.md)。验证使用独立数据库与本机模拟提供方，不混入真实账户、积分或 API 凭据。

正式开发数据库仍等待用户首次初始化 root；原 5 个项目届时登记为该 root 的个人项目。旧全局 MCP/A2A 凭证保持关闭，不能自动取得 root 权限。个人偏好和项目格式保留。

项目内容与迁移备份一致：907 个原文件中 906 个 SHA-256 完全匹配，唯一差异是 Finder 的 `swordWallBattle/.DS_Store`；7 张原画布已通过新认证和项目所有权接口读取。原始备份保留。

成员浏览、下载和主动上传团队资产，owner/root 负责重命名、删除与成员管理；退出或移除成员不删除已共享副本。只有当前同团队成员可以划转个人可用积分，团队不持有钱包。
