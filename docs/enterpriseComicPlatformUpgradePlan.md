# 万象点点企业漫剧平台完整改造方案与实施计划

**版本**：v1.0  
**编制日期**：2026-10-29（Asia/Shanghai）  
**适用对象**：万象点点企业版、漫剧/短剧订单交付团队、产品、工程、客户成功和安全团队

## 1. 文档目的

本方案把前期京东云灵境实测、灵境公开资料、成熟产品调研和万象点点仓库核实结果合并为一份可执行的企业化改造基线。目标是让平台能够承接多个企业客户的漫剧订单，完成从创意、剧本、资产、分镜、生成、审片、审批、合成到交付的可追溯生产闭环。

本方案采用四种证据等级：

- **A：真实实测**：在已登录灵境租户中完成操作并读取页面结果、播放器时长或余额变化。
- **B：公开资料**：产品页、帮助文档、公开功能说明或成熟产品官方文档，只能证明产品声明或设计模式。
- **C：仓库核实**：从当前源码、数据库结构和现有生产规范中确认已有底座。
- **D：待 POC/厂商确认**：公开资料不足，或受账号、额度、协议、并发、地区和商业合同影响。

## 2. 管理层结论

万象点点应定位为“企业可控的漫剧生产操作系统”。灵境最值得吸收的是业务包装：创意直接进入剧集、主体资产、分镜和视频生成链路；我方应保留并放大无限画布、供应商适配、自托管、数据控制、MCP/A2A 和插件扩展能力。

当前可以启动 **P0 企业底座改造**，但不能把现状承诺为整集商用交付。首个版本必须先跑通一条 60 秒标准样片的“提交—生成—审片—重拍—批准—导出”闭环，再扩展复杂剪辑、实时多人协同、SSO/SCIM 和私有化交付。

六项最高优先级能力是：

1. 项目级 RBAC；
2. 资产版本与权限；
3. 审批与审片流；
4. 组织/项目预算控制；
5. 任务幂等与并发冲突处理；
6. 完整审计和可导出证据包。

## 3. 已完成的灵境基线

### 3.1 真实测试结果（A 级）

测试输入为“夜班保安发现会说话的旧收音机并寻找失主”，16:9、5 集、每集 0–1 分钟，脚本 ID 为 `sd_Mzg`。

|阶段|已观察结果|费用/状态|企业含义|
|---|---|---|---|
|分集剧本|5 集完成，共 7 个场景|未扣费，余额 1,600|验证了从创意快速建立剧集骨架|
|主体资产|4 个角色、4 个场景、2 个道具，共 10 个资产完成|消耗 600，约 60/资产|得到资产成本基线，但连续性和版本仍需人工治理|
|分镜脚本|5 集完成；第 1 集 16 个镜头，总时长 57 秒|未扣费|镜头字段足以作为生成和审片的输入|
|视频生成|第 1 集计划 5 个片段；片段 01、02、03 已生成；片段 01、03 播放器核验为 4 秒；片段 04、05 各提交一次后超过 6 分钟无输出|视频阶段余额从 1,100 变为 539；已完成片段净减少 561，约 187/片段；成功任务页面报价 184，差额需账单确认|验证了最低规格片段链路，同时暴露出挂起、无错误码、无任务历史和整集无法合成的问题|

其他观察：片段 02 首次提交等待约两分钟无输出，刷新后重试成功；出现过一次 `Failed to fetch dynamically imported module`，刷新后恢复；开启合规素材审核时日志提示“使用素材库功能，请先同意 Seedance 2.0 模型使用承诺书”，页面没有可点击签署入口。协议不能视为已签署，企业版必须将协议、素材授权和审核结果作为生成前置 Gate。

### 3.2 团队协作单账号盘点

按授权只做了单账号只读盘点，没有发送邀请、修改权限、上传或共享新数据。灵境《团队会员使用手册》公开描述了创建者、管理员、协作者、查看者四类角色，空间配额、团队资产、画布权限、到期只读和席位/灵感值规则。这些属于 B 级公开资料，不等于当前租户已通过。

仍需第二身份和双会话才能验证：实际邀请、角色越权、项目共享、移除成员后的访问失效、双人并发编辑、重复计费、审批、预算隔离和审计导出。

### 3.3 证据边界

灵境的完整视频质量、批量并发、失败重试、整集合成、SSO/SCIM、私有化、数据驻留、SLA、账单对账和团队成员级行为均属于 D 级或待正式 POC 项目。不能把公开宣传、功能入口或页面按钮当作企业验收结果。

## 4. 当前仓库能力与差距（C 级）

### 4.1 可复用底座

- Vue Flow 无限画布、节点/边、资产库、历史、远程节点和 Agent 画布工具。
- 图片、视频、音频节点；3D 导演节点支持场景、动作、运镜、关键帧和导出。
- FFmpeg 拼接、SSE 进度和取消；`generationJobs`、`generationOutputs`、供应商/模型配置和价格表。
- 用户、工作区、团队、邀请、团队共享资产、积分钱包、积分账本、积分划转和 `auditEvents` 基础。
- Docker/桌面端、自托管、供应商适配、MCP/A2A、插件和 Skill 扩展。

### 4.2 关键差距

- 画布仍是主要业务载体，缺少 `project/season/episode/scene/shot/take` 一等业务对象。
- 生成任务缺少稳定的项目/集/场/镜头/资产版本关联，挂起任务缺心跳、超时、失败码、人工接管和恢复策略。
- 团队角色主要是 workspace/team 层级，缺项目级角色、资源 ACL、审片角色和审批状态机。
- 团队资产缺主参考、变体、服装状态、授权、影响分析、下载/复制/导出权限。
- 已有个人钱包和积分账本，但缺组织/客户/项目/镜头预算、成本预留、失败/重拍成本和供应商账单对账。
- 已有 FFmpeg 底座，但缺最小多轨时间线、字幕/音频轨和 MP4/SRT/manifest 交付包。

### 4.3 当前闭环可执行性审计

|闭环环节|当前状态|源码依据/阻断点|结论|
|---|---|---|---|
|项目创建|部分可用|已有 workspace、personalProjects 和画布文件；没有 productionProject、episode、scene、shot 的业务接口和页面。|只能创建工作区/画布，不能创建可追踪的漫剧生产项目。|
|权限|部分可用|已有 workspace/team owner、member、邀请和团队资产访问；没有项目成员、角色权限集合和资源 ACL。|能管理团队成员，不能执行项目级 RBAC 验收。|
|生成|可用但未业务化|`/api/ai/media/generate`、`generationJobs`、积分预留/结算和幂等键已存在；任务与镜头无关联，生成请求仍以长请求/文件结果为主。|可以生成媒体，不能形成镜头级持久生产任务。|
|预算|个人级可用|`wallets`、`creditLedger`、报价、reserve/capture/release 已存在；没有客户/组织/项目预算、预警和超额审批。|能扣个人积分，不能做企业项目预算控制。|
|审片|输出审核可用|`generationOutputs` 支持 pending/usable/waste，管理员可标记输出；没有评论、@、时间码批注、review/approval、版本锁定。|能标记废片，不能跑企业审片审批流。|
|重拍|手工可做|可以再次调用生成接口；没有 generationAttempt/clipVariant/adoptedVariantId 和局部重跑关系。|能重新生成文件，不能证明是同一镜头的可追溯重拍。|
|MP4/SRT/manifest|底层能力分散|FFmpeg execute/events/download 和视频节点存在；没有 timeline、字幕轨、音频轨、合成任务、SRT/manifest 导出接口。|可手工调用 FFmpeg，不能从项目一键导出交付包。|
|审计包|基础审计可用|`auditEvents` 已记录账户、团队、插件等动作，且有管理员用量 CSV；缺项目动作、审批前后状态、交付包和统一导出。|有审计底座，不能满足企业订单证据链。|

因此，**现在不能直接跑通“项目创建 → 权限 → 生成 → 预算 → 审片 → 重拍 → 批准 → MP4/SRT/manifest/审计包”完整闭环**。当前最多能演示“工作区/画布 → 媒体生成 → 个人积分结算 → 手工 FFmpeg”，其中项目、权限、预算、审批和交付追踪都缺业务连接。

## 5. 对标结论：从成熟产品吸收什么

|能力|灵境公开基线|成熟产品补充|我方采用方式|
|---|---|---|---|
|项目级 RBAC|创建者/管理员/协作者/查看者，区分空间、资产、画布权限|Figma 的直接邀请、团队、组织、文件夹继承；Jira 的 permission scheme|组织 → 工作空间 → 项目 → 资源四层授权，角色绑定权限集合，资源 ACL 只能收紧权限|
|资产权限|共享资产按角色区分查看、引用、下载、删除|Figma 展示继承权限、直接邀请者、分享链接和发布动作|资产版本记录来源、授权、继承链、下载/复制/导出权限；交付只能引用批准版本|
|审批流|公开资料区分评论/标注和画布权限|Frame.io 的媒体审阅、意见、退回和批准|`review/approval/comment/decision` 分离，审批绑定具体候选和时间线版本|
|预算控制|席位、团队/个人灵感值资产池、空间预算和用量描述|企业软件常见预算预警、审批、账单维度和用量导出|组织预算、项目预算、预留、实际成本分开；失败和重拍单独核算|
|并发处理|灵境双账号并发本轮未验证|Figma 的多人文件协作和权限继承|先用 revision、乐观锁、冲突提示、幂等键和事件广播，后续再评估 CRDT|
|完整审计|公开资料提到审计与用量，但字段/导出待确认|Jira 提供项目权限和应用审计活动|记录操作者、对象、前后状态、结果、requestId、IP、设备和时间，支持 JSON/CSV 导出|

## 6. 目标产品形态

### 6.1 三层结构

1. **业务层**：客户订单、生产项目、剧集、场、镜头、资产、审片、审批、时间线、交付包。企业用户主要在这一层工作。
2. **编排层**：画布节点、Agent、Skill、模型路由、提示词模板和供应商适配。画布是业务层的可视化编排视图，不是唯一事实来源。
3. **执行层**：持久任务队列、对象存储、媒体处理、预算计费、审计、监控和故障恢复。

### 6.2 核心业务对象

`customerOrder`、`productionProject`、`season`、`episode`、`scene`、`shot`、`take`、`asset`、`assetVersion`、`generationAttempt`、`clipVariant`、`review`、`approval`、`timeline`、`delivery`、`budgetLedger`、`auditEvent`。

画布只保存布局、连线、编排参数和业务对象引用；业务对象负责状态、版本、权限、成本和交付事实。

### 6.3 P0 数据模型

- `productionProject`：`id`、`workspaceId`、`customerId`、`ownerId`、`status`、`budgetCents`、`createdAt`、`updatedAt`。
- `projectMember`：`projectId`、`userId`、`role`、`scope`、`status`、`invitedBy`。
- `rolePermission`：`role`、`action`、`resourceType`、`effect`。
- `resourceAcl`：`resourceType`、`resourceId`、`principalType`、`principalId`、`action`、`effect`、`expiresAt`。
- `episode/scene/shot`：编号、标题、目标时长、对白、旁白、景别、运镜、光影、音效、提示词、状态和当前版本。
- `assetVersion`：角色/场景/道具/风格/音频类型、主参考、变体、服装状态、授权状态、来源和影响范围。
- `generationAttempt`：项目上下文、供应商、模型、提示词快照、参数快照、参考资产快照、幂等键、状态、重试次数、估算/预留/实际成本、失败码和输出。
- `clipVariant`：镜头、任务、URI、时长、质量/审片状态、创建人和创建时间。
- `review/approval`：审阅对象、评论、决定、操作者、时间、版本和下一步动作。
- `budgetLedger`：预算范围、预警阈值、预留、释放、实际扣费、币种/积分、来源任务和对账状态。
- `auditEvent`：租户、操作者、动作、对象、前状态、后状态、结果、requestId、IP、userAgent、时间和元数据。

## 7. 六项企业能力的详细改造要求

### 7.1 项目级 RBAC

角色建议：`owner`、`producer`、`writer`、`director`、`artist`、`editor`、`reviewer`、`viewer`。权限按资源和动作表达：`read`、`create`、`edit`、`generate`、`retry`、`delete`、`comment`、`review`、`approve`、`export`、`invite`、`manageBudget`。

规则：服务端默认拒绝；项目成员不能自动访问其他项目；资源 ACL 只能收紧继承权限；批准版本和已交付版本禁止原地修改；所有权限变化写入审计。

### 7.2 资产权限与连续性

资产必须有主参考版本和变体版本。镜头只能引用明确批准的 `assetVersion`；替换主参考前生成影响列表，不能覆盖历史成片；授权过期、肖像/声音授权缺失或客户素材范围不明时阻止交付；下载、复制、外链和对外发布是独立权限。

### 7.3 审批与审片

镜头候选状态：`draft → generating → review → changesRequested → approved`；退回必须创建新 `generationAttempt` 和新 `clipVariant`；`approved` 版本锁定，采用其他候选时保留原候选。项目状态：`draft → scripted → storyboarded → generating → editing → review → approved → delivered`。

评论要绑定镜头、时间码或画面区域，支持 @、附件、解决/重开和审阅意见导出。未批准的候选不能进入交付包。

### 7.4 预算、额度与成本

生成前依次执行权限检查、协议/授权检查、预算检查和幂等检查。成本分为 `estimatedCost`、`reservedCost`、`actualCost`；失败、废片、重拍、人工后期、供应商和模型维度均需保留。项目预算达到 60%/80%/100% 分级预警，100% 默认阻断，只有 `producer/owner` 批准才允许超额。

### 7.5 并发与冲突

第一版采用版本号和乐观锁：提交时携带 `baseRevision`，服务端发现版本变化就返回冲突详情，不静默覆盖。任务采用 `projectId + shotId + generationAttemptId` 幂等键；重复回调只更新原任务。删除和改名使用软删除、事件广播和可恢复窗口。刷新、断线和 worker 重启不能丢失任务状态。

### 7.6 完整审计

至少记录登录、成员邀请/接受/移除、角色变化、资产上传/授权/下载/删除、提示词和参考图修改、任务提交/取消/重试、预算预留/释放/扣费、评论、审批、交付导出和删除。审计日志应支持按项目、用户、动作、对象、时间和结果筛选，导出 JSON/CSV，敏感素材和提示词按权限脱敏。

## 8. 生产任务与交付闭环

### 8.1 任务状态机

`quoted → reserved → queued → running → succeeded | failed | cancelled | timedOut | needsManualReview`。

任务必须有心跳、进度、超时时间、重试上限、失败类别、供应商回调去重和人工接管状态。合规协议未确认、授权不足和预算不足属于不可盲目重试的阻断类错误。

### 8.2 标准生产流程

1. 创建客户订单和生产项目，设置品牌、交付格式、预算和验收人。
2. 导入创意，生成剧集、场景和镜头；客户确认剧集包。
3. 建立角色、场景、道具主参考与授权记录。
4. 生成分镜，导演/编剧审阅后锁定镜头版本。
5. 按镜头提交生成任务，显示预估、预留、实际成本和候选版本。
6. 审片人评论、退回或批准；退回只重跑受影响镜头。
7. 时间线组装画面、对白、旁白、BGM、SFX 和字幕。
8. 导出 MP4、SRT、manifest JSON、源文件清单、成本报告和审计包。

### 8.3 最小交付包

第一版交付必须包括：可播放 MP4、SRT 字幕、manifest JSON、镜头/候选清单、使用的模型和提示词快照、资产授权状态、成本明细、审批记录和版本哈希。

## 9. 分阶段实施计划

### S0：标准化与冻结指标（1–2 周）

产出一套 5 集、每集 30–60 秒的标准剧集包，包括剧本、资产清单、分镜、提示词、参考图、目标输出和验收人。冻结成功率、耗时、队列等待、重试次数、生成成本、废片成本、连续性评分、字幕错误数和人工修改时长。

**Gate**：同一输入可在灵境和我方复测；所有结果可导出 JSON/CSV；成本单位和时间口径一致。

### S1：企业底座纵切（3–5 周）

增加生产项目和 `episode/scene/shot` 最小实体，接入现有 `generationJobs`、积分账本和审计；实现项目成员、角色权限、预算预留、幂等键和任务状态；提供审片列表。

**Gate**：三角色跑通“提交—生成—评论—退回—重拍—批准”；越权被拒绝；预算超额被阻断；重复请求不重复扣费；所有动作可审计。

### S2：资产 DAM 与连续性（3–4 周）

实现主参考、变体、版本、服装/状态、授权、引用关系、搜索、批量替换和影响分析；把资产引用从画布节点升级为业务对象引用。

**Gate**：同一角色跨 10 个镜头引用同一批准版本；替换主参考不会覆盖旧版本；授权过期阻止交付。

### S3：持久任务与局部重跑（4–6 周）

统一图片/视频/音频/FFmpeg 任务，加入依赖 DAG、心跳、超时、指数退避、取消、断点恢复、供应商 fallback、人工接管和成本对账。

**Gate**：单镜头失败只重跑该镜头；刷新/断线不丢状态；失败、重拍和废片成本可分摊；任务状态可导出。

### S4：时间线与企业交付（4–6 周）

基于 FFmpeg 实现最小多轨时间线：镜头排序、in/out、硬切、字幕轨、音频轨、BGM/SFX、基础混音和导出。复杂转场、调色和口型同步后置。

**Gate**：标准 60 秒样片一次导出 MP4、SRT、manifest；画面时长与分镜一致；字幕时间码可复核；另一台机器可按 manifest 重建。

### S5：企业运营与私有化（6–10 周）

补对象存储/CDN、备份恢复、HA、队列监控、SLO/告警、Webhook/API、SSO/OIDC/SAML、SCIM、内容安全、版权检测、数据驻留、部署手册和客户运维接口。

**Gate**：通过安全评审、恢复演练、并发压测、供应商故障切换和一个企业客户试点上线。

## 10. 企业 POC 与市场化验收

### 10.1 标准 POC 包

每个客户使用 1 个 5 集短剧，每集 30–60 秒；4 个角色、4 个场景、2 个道具；每集 12–16 个镜头；一套品牌色、字幕规范和授权材料。先做首集 3–5 个镜头验证，再完成首集全量交付。

### 10.2 POC 通过门槛

- 剧本、资产、分镜结构化完整率 ≥ 95%。
- 镜头任务成功率 ≥ 95%；失败只局部重跑，不重跑整集。
- 每个候选可反查模型、提示词、参考资产、操作者、时间和成本。
- 首集输出可播放 MP4、SRT 和 manifest；字幕无阻断错误。
- 客户能按项目、集、镜头查看预算和实际成本。
- 客户能完成成员权限、审批、审计导出和交付下载。

### 10.3 必须向灵境/供应商书面确认

1. Seedance 2.0 承诺书的适用范围、接受主体、数据处理和企业批量流程。
2. 模型可用区域、配额、限流、排队、超时、失败和重试计费规则。
3. 视频片段、重拍、智能剪辑、整集导出的单价和账单明细。
4. API 回调、幂等、任务保留、并发上限、断点恢复和错误码。
5. 组织角色、项目权限、成员预算、用量分析、账单和审计导出。
6. SSO/OIDC/SAML、SCIM、私有化、数据驻留、备份、SLA、RPO/RTO。
7. 客户素材、生成结果、提示词和微调数据的所有权、训练开关、删除和导出机制。
8. 内容安全、版权检测、肖像/声音授权和违规申诉流程。

## 11. 成本与运营控制

灵境本轮只能提供外部积分基线：10 个主体资产消耗 600 灵感值；已完成视频片段对应余额净减少约 187/片段，页面报价曾显示 184。灵感值不能直接换算人民币，必须以账单或合同确认。

我方成本中心必须同时保留预估、预留和实际三种金额，并按客户、订单、组织、项目、集、场、镜头、资产、供应商、模型、成功/失败/废片、重拍和人工后期拆分。财务导出不能依赖个人余额截图。

## 12. 风险与控制

|风险|控制措施|
|---|---|
|把画布当数据库|剧集对象作为权威源，画布只保存编排和快照|
|供应商能力漂移|供应商适配层、能力探测、fallback、价格快照和定期 POC|
|重复扣费|幂等键、成本预留、回调去重、账本和任务审计|
|角色/场景连续性失控|主参考版本、引用关系、影响分析和批准版本锁定|
|只有片段无法交付整集|P1 时间线、MP4/SRT/manifest Gate，不以片段数量代替交付|
|企业数据越权|租户隔离、资源 ACL、授权状态、对象存储签名 URL、审计和删除策略|
|预算失控|预估/预留/实际成本、分级预警、超额审批和失败/重拍单列|
|范围膨胀|P0 纵切未通过前不启动社区、复杂特效、全量模型商城和自动渠道发布|

## 13. 首个开发迭代任务清单

第一迭代只做可交付的 P0 纵切：

1. 新增 `productionProject`、`episode`、`scene`、`shot` 和 `projectMember` 最小对象。
2. 将一个现有视频生成节点接入 `generationAttempt`，保存项目、镜头、模型、提示词、参考和成本快照。
3. 复用现有积分账本，增加项目预算预留、释放、实际扣费和幂等检查。
4. 实现 `owner/producer/writer/reviewer/viewer` 最小权限矩阵和服务端授权函数。
5. 将候选输出放入审片列表，支持评论、退回、批准和版本锁定。
6. 为成员变化、任务、成本、审批、导出和删除写入统一 `auditEvent`。
7. 用 3 个镜头跑通一次“提交—生成—重拍—批准—导出 manifest”。

第一迭代不同时开发作品社区、复杂转场、全量模型商城、自动发布渠道和实时 CRDT。只有 P0 纵切通过真实验收，才进入规模化企业订单交付。

## 14. 最终决策

现在适合启动企业级改造的 P0 阶段，原因是底层生成、画布、账本、任务、团队和审计基础已经存在，且灵境实测已经明确了企业生产必须解决的挂起、成本、合规、版本和整集交付问题。

正式对外承诺企业订单前，必须完成 S1–S4 的验收，至少交付一集可播放成片和完整证据包；SSO/SCIM、私有化、数据驻留、安全评审和 SLA 则作为企业客户上线前的 S5 Gate。<br>

**本方案不是“照搬某个平台界面”，而是把成熟平台的业务闭环、权限治理和审片交付能力转化为我方可控、可审计、可替换供应商的产品架构。**
