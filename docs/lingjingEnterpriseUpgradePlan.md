# 企业漫剧生产改造计划

**适用对象**：万象点点企业版、漫剧/短剧订单交付团队、产品与工程团队

**依据**：2026-10-27 在京东云灵境登录租户中的真实测试、灵境公开产品页和文档、万象点点当前仓库源码与生产规范。

**本计划的目的**：把现有的通用 AI 画布和媒体生成底座改造成可以承接多企业订单的漫剧生产系统。画布继续作为自由编排入口，但剧集、镜头、资产、任务、审批和交付必须有稳定的结构化数据作为权威来源。

## 1. 决策结论

万象点点不需要复制灵境的全部界面，而应吸收其最有价值的业务包装：从创意直接建立剧集、自动提取主体资产、自动生成分镜、按镜头生产和片段重拍。我们的差异化放在企业可控性：供应商可替换、自托管、数据驻留、可审计、可按客户订单核算成本、可接入现有系统。

当前仓库已经具备可复用的底层能力：Vue Flow 无限画布和节点系统、文档/Markdown/Tiptap、图片/视频/音频节点、3D 导演台、FFmpeg 拼接、SSE 进度与取消、generationJobs/generationOutputs、积分账本与价格表、users/workspaces/teams/teamAssets/auditEvents。缺口集中在业务对象、持久队列、版本审批、时间线和企业治理。

### 2.2 证据使用规则

- **A：真实实测**。可以进入基线和验收，例如本次剧本、主体资产、分镜和费用。
- **B：公开资料**。只能说明厂商声明或入口存在，例如模板、智能剪辑、团队治理。
- **C：仓库核实**。说明已有底座和复用点，不等于漫剧业务闭环已完成。
- **D：待厂商/POC**。公开资料不足或受租户、余额、承诺书影响，例如完整视频交付、SSO/SCIM、私有化、数据驻留、SLA。

## 3. 产品边界和权威数据

### 3.1 三层产品结构

1. **业务层**：生产项目、剧集、场、镜头、资产、审批、时间线、交付包。企业用户日常操作停留在这一层。
2. **编排层**：画布节点、Agent、Skill、模型路由、提示词模板和供应商适配。画布是业务层的可视化编排视图。
3. **执行层**：持久任务队列、对象存储、媒体处理、用量计费、审计、监控和重试。

剧集对象是权威来源。画布保存布局、连线和编排快照；画布节点不能独立产生一份脱离剧集的“隐藏事实”。

### 3.2 核心数据模型

以下字段是 P0 最小集合，实际表名遵守仓库的小驼峰命名规范。

- productionProject：id、workspaceId、customerId、title、status、budgetCents、ownerId、createdAt、updatedAt。
- episode：id、projectId、number、title、status、targetDurationMs、currentVersionId。
- scene：id、episodeId、number、title、locationAssetId、continuityNotes。
- shot：id、sceneId、number、durationMs、shotType、camera、lighting、dialogue、narration、sound、prompt、status、adoptedVariantId。
- assetVersion：id、projectId、kind（character/location/prop/style/audio）、name、version、sourcePrompt、referenceUri、costumeState、authorizationState、status。
- generationAttempt：id、projectId、episodeId、sceneId、shotId、assetVersionId、kind、provider、model、promptSnapshot、parameterSnapshot、referenceSnapshot、status、attemptNumber、estimatedCostCents、actualCostCents、failureCode、outputIds、createdBy、createdAt。
- clipVariant：id、shotId、generationAttemptId、uri、durationMs、reviewState、createdAt。
- review、approval、timeline、timelineTrack、timelineItem、delivery、budgetLedger、auditEvent：分别记录审片、审批、时间线、交付、成本和审计。

所有生成输出必须能反查到 project/episode/scene/shot 或 assetVersion，不能只挂在用户或画布节点上。

## 4. 生产状态机

### 4.1 剧集状态

draft → scripted → storyboarded → generating → editing → review → approved → delivered。

- rejected 只能回到当前生产阶段，不得自动覆盖已批准版本。
- delivered 后仍允许创建新版本，但必须标注为修订交付并保留原交付包。
- 状态推进由权限控制，并写入审计事件。

### 4.2 镜头状态

draft → ready → generating → review → approved。退回时为 changesRequested，重拍只创建新的 clipVariant 和 generationAttempt。采用候选后写入 adoptedVariantId，不能删除其他候选。

### 4.3 任务状态

queued → running → succeeded | failed | cancelled。任务必须幂等，使用业务键（projectId + shotId + generationAttemptId）防止重复扣费。供应商回调重复到达时只更新同一任务；超过重试上限进入人工处理队列。

## 5. 六阶段实施路线

### S0：标准剧集包和指标冻结

产出一套 5 集、每集 0–1 分钟的标准输入，包含剧本、角色/场景/道具清单、分镜、提示词、参考图和目标交付。固定记录字段：成功率、耗时、队列等待、重试次数、生成成本、废片成本、镜头连续性评分、字幕时间码错误数、人工修改时长。

**Gate**：同一输入可以在灵境和万象点点重复运行，指标含义一致；所有结果都能导出 JSON/CSV。

### S1：组织、项目、权限、预算和审计

复用 users/workspaces/teams/auditEvents，新增项目成员表和项目角色：owner、producer、writer、director、artist、editor、reviewer、viewer。先实现项目级 RBAC 和预算，再接 SSO/OIDC；SAML/SCIM 放 S5。

**Gate**：编剧提交，审片人批准，查看者只能读；越权请求返回拒绝且产生审计记录；预算超额必须审批。

### S2：资产 DAM、版本和连续性

建立角色、场景、道具实体与 assetVersion。支持主参考、变体、服装/状态、授权状态、标签、搜索、批量引用和影响分析。素材替换时列出所有受影响镜头；生成候选不能覆盖主参考。

**Gate**：同一角色跨 10 个镜头引用同一批准版本；替换版本后旧版本仍能重建历史成片。

### S3：剧本—分镜—生成—重拍编排

把现有文档/Agent 能力接到 episode/scene/shot。生成请求进入持久任务中心，统一接入图片、视频、音频和 FFmpeg。实现依赖 DAG、幂等键、超时、指数退避、取消、断点恢复、局部重跑、供应商 fallback 和成本预估。片段重拍创建 clipVariant，保留提示词、模型、参考资产、价格和失败原因。

**Gate**：单镜头失败只重跑该镜头；刷新页面不丢状态；每个候选能显示“谁、何时、用什么模型、花了多少钱”。

### S4：最小时间线和交付

基于现有 FFmpeg 实现最小多轨时间线：镜头顺序、in/out、硬切、字幕轨、音频轨、BGM/SFX、基础混音。第一版导出 MP4、SRT、manifest JSON 和源文件清单；转场、复杂调色和口型同步可以后置。

**Gate**：标准 60 秒样片一次导出成功，画面时长与分镜一致，字幕时间码可复核，导出包可被另一台机器重建。

### S5：企业化运营和私有化

补对象存储/CDN、备份恢复、HA、队列监控、SLO/告警、Webhook/API、SSO/OIDC/SAML、SCIM、内容安全、版权检测、数据驻留、部署手册和客户运维接口。

**Gate**：完成安全评审、恢复演练、并发压测、供应商故障切换和一个企业客户试点上线。

## 6. 队列、计费和成本控制

### 6.1 任务队列

- API 创建任务时先做参数校验、权限检查、预算检查和幂等检查。
- 任务记录估算成本和额度预留；只有供应商确认接受后才记实际成本。
- worker 从持久队列取任务，更新心跳和进度；前端通过 SSE/WebSocket 订阅状态。
- 供应商错误按可重试、不可重试、需人工确认分类；模型合规承诺、版权阻断等不得盲目重试。
- 取消任务释放未使用预留；已产生费用必须保留为实际成本。

### 6.2 成本模型

同时保留三种金额：estimatedCost、reservedCost、actualCost。成本维度至少包括组织、客户、项目、集、场、镜头、资产、供应商、模型、任务类型、成功/失败/废片、重拍和人工后期。

灵境本轮可作为外部基线：10 个主体资产 600 灵感值，约 60/资产；视频片段报价受时长、分辨率、音频和模型影响，当前观察到 Seedance 2.0 fast 默认 1,038、Seedance 2.0 最低配置 184，视频阶段页面余额净减少 187。不能直接把灵感值换算成人民币，需从厂商账单或合同确认兑换口径；报价与余额扣减差异必须在企业账单接口中保留原始快照。

### 6.3 企业预算规则

- 项目创建时设置预算和预警阈值（例如 60%、80%、100%）。
- 预算不足时允许查看和审片，禁止提交新生成任务，除非有 producer/owner 审批。
- 失败、废片和重拍成本单独展示；不能只显示成功输出成本。
- 月度账单支持按客户订单、项目、集和镜头导出，供财务对账。

## 7. 企业协作和安全

P0 实现项目级 RBAC、审批、评论、锁定、版本回滚和审计；P2 再实现 SSO/SCIM 等身份集成。审计至少记录登录、成员变化、资产授权、提示词修改、任务提交/取消/重试、成本变更、审批、交付下载和删除。

数据层需要租户隔离、对象存储权限 URL、敏感提示词与客户素材的访问控制、删除/保留策略、备份加密和导出审计。涉及客户肖像、品牌、配音和音乐时，资产必须带授权状态；授权过期时阻止交付而不是只显示提醒。

### 7.1 灵境团队协作单账号盘点与补测矩阵

本轮按授权只做单账号只读盘点，不发送邀请、不改变成员权限、不上传或共享新数据。灵境《团队管理》公开文档描述了创建者、管理员、协作者、查看者四类角色，以及空间配额、团队资产、画布编辑和到期只读等规则；这些是 B 级公开资料，不能当成当前租户的成员级实测结果。当前没有第二个测试身份和双会话，因此以下项目保持“待租户实测”。

公开对标要点：创建者负责空间创建/解散和配额/席位配置；管理员可邀请/移除成员和调整普通成员角色；协作者可在空间内创作；查看者只读但可评论/标注。团队资产的查看、引用、下载、删除权限按角色区分；团队会员到期后空间进入只读预览，上传、提交作品和团队画布编辑受限。团队会员按席位售卖，赠送灵感值按月发放、月末清零，团队与个人会员灵感值共享资产池。来源：[灵境团队会员使用手册](https://docs.jdcloud.com/cn/lingjing/TeamVip)。

### 7.2 六项能力的成熟产品基准与落地方案

以下结论来自灵境团队会员手册、Figma 权限文档、Frame.io 审片文档和 Atlassian Jira 权限/审计文档，均为 B 级公开资料。它们用于设计基线，不表示灵境当前租户已经通过相同测试。

|预算控制|灵境公开描述席位、团队/个人灵感值资产池、空间预算和用量管理。|拆分 seat、organizationBudget、projectBudget、reservation、actualCost；提交前预算检查和成本预留，失败/重拍独立计费。|80% 预警、100% 阻断；producer 审批可超额；账单按客户/项目/集/镜头导出。|
|并发冲突|Figma 的多人文件协作和权限继承适合作为编辑参考；灵境双账号并发本轮未验证。|画布使用 revision + 乐观锁 + 冲突提示；生成任务使用幂等键；删除/改名软删除并广播事件。|两会话不静默覆盖；相同幂等键只产生一个计费任务；断线重连后状态可恢复。|
|完整审计|Atlassian Jira 提供权限方案和应用审计活动文档；灵境公开资料提到审计/用量，但字段和导出仍待确认。|auditEvent 记录 tenant、actor、action、object、before/after、result、requestId、ip、userAgent、createdAt；支持筛选、保留、导出。|成员、资产授权、提示词、任务、成本、审批、导出、删除均可查询并导出 JSON/CSV。|

#### P0 数据与服务最小集合

新增或补齐 `projectMembers`、`rolePermissions`、`resourceAcl`、`assetVersions`、`reviews`、`approvals`、`budgetLedger`、`generationAttempts`、`auditEvents`。所有写接口统一经过 `authorize(actor, action, resource)`、`checkBudget(scope, estimate)`、`idempotencyKey` 三个门；状态变化使用事务写入业务表和审计事件。实时协同可以先采用版本号和冲突提示，等 P0 纵切稳定后再引入更复杂的 CRDT。

#### P0 纵切验收场景

用一个项目、三个角色和三个镜头跑通：编剧提交分镜 → 生成任务预留预算 → 审片人评论并退回 → 新版本重拍 → 审片人批准 → 查看者只读查看 → 导出 MP4/SRT/manifest 和成本/审计包。验收必须覆盖一次越权、一次重复提交、一次预算超额和一次并发冲突；任何失败都要保留原版本、成本和审计记录。

## 8. 市场化 POC 方案

### 8.1 标准 POC 包

每个潜在客户提供：1 个 5 集短剧、每集 30–60 秒；4 个角色、4 个场景、2 个道具；每集 12–16 个镜头；一套品牌色和字幕规范。客户提供可用素材授权和验收人。

### 8.2 交付过程

1. 导入创意和品牌约束，生成剧集包。
2. 客户确认角色/场景/道具主参考。
3. 生成分镜并进行一次审片。
4. 只生成首集 3–5 个镜头作为模型和风格验证。
5. 生成全首集并完成一次片段重拍。
6. 导出 MP4、SRT、manifest 和成本报告。

### 8.3 POC 通过门槛

- 剧本、资产、分镜结构化数据完整率 ≥ 95%。
- 镜头任务成功率 ≥ 95%；失败可局部重跑，不能导致整集重跑。
- 每个输出候选可追溯到模型、提示词、参考资产、成本和审批人。
- 首集可以交付可播放 MP4、SRT 和 manifest；字幕时间码无阻断错误。
- 客户能够按项目、集、镜头查看预算和实际成本。
- 企业客户能完成成员权限、审批、审计导出和交付下载。

## 10. 风险与取舍

|风险|表现|控制|
|---|---|---|
|把画布当数据库|节点删除或复制后业务事实丢失|剧集对象做权威源，画布只保存编排和快照|
|供应商能力漂移|模型下线、租户无模型、价格变化|供应商适配层、能力探测、fallback、报价快照和 POC 基线|
|重复扣费|刷新或回调重放导致重复生成|幂等键、成本预留、回调去重、任务审计|
|连续性失控|角色服装、场景和道具跨镜头漂移|主参考版本、引用关系、影响分析和审片 Gate|
|后期不可交付|只有片段没有整集、字幕或音频|P1 最小时间线、MP4/SRT/manifest 验收|
|企业数据风险|客户素材、肖像、品牌或配音越权|租户隔离、授权字段、对象存储访问控制、审计和删除策略|
|范围膨胀|先做社区、复杂特效而遗漏订单闭环|按 S0–S5 Gate 排序，P0 未通过不启动 P2|

## 11. 首个开发迭代建议

第一迭代只做可交付的 P0 纵切：创建 productionProject 和 episode/scene/shot；把现有一个生成节点接入 generationAttempt；增加 projectId/episodeId/sceneId/shotId 和 attempt/version 关联；完成项目角色、预算预留、任务状态和审计；把 3 个镜头的候选显示在审片列表中。随后用标准 60 秒样片跑通一次“提交—生成—重拍—批准—导出 manifest”的闭环。

不要在这一迭代同时开发作品社区、复杂转场、全量模型商城或自动发布渠道。只有 P0 纵切真实跑通，才有足够证据估算后续企业订单交付能力。
